## 1. 할 것

### P0 키 — 바꿀 수 있게, 그리고 바꾸기

- **0-1 KEK 교체 도구** — 새 KEK로 테넌트 키(DEK)와 HandSOS 접속 정보만 다시 감싼다. 손님 이름·전화 자체는 다시 암호화할 필요가 없다(봉투 암호화: KEK → 테넌트 DEK → 이름·전화). 미리 보기(dry-run) → 바꾸기 → 이름이 풀리는 손님 수가 전과 같은지 확인. 바꾸는 동안 앱은 옛 키로도 읽는다(옛 키를 잠깐 함께 둔다) — 이름이 '고객'으로 보이는 순간이 없게.
- **0-2 서비스 키 교체 순서표** — Supabase에서 새로 발급 → 맥 `.env` · Cloudflare · GitHub 비밀값을 순서대로 바꾸고, 바꾼 뒤 확인할 것(수집 1회 · 앱 로그인 · sync-health). 키 값은 채팅에 붙이지 않는다.
- 이미 바꿨다면 0-1만 한다(다음 교체를 위해 — 키는 주기적으로 바꾸는 게 원칙이다).

### P1 데이터 지키기 — 주 1회 백업

- 맥이 일요일 수집 직후, 앱에만 있는 데이터를 매장별로 묶어 **암호화 파일**로 남긴다(최근 8주 보관). 손님은 고객번호(ext_id)로 이어 붙인다 — DB를 새로 만들고 다시 수집한 뒤에도 되살릴 수 있게.
- 되살리기 스크립트 + 왕복 테스트(백업 → 지움 → 되살림 → 같다).
- sync-health 가 '마지막 백업'도 함께 본다 — 8일 넘게 없으면 실패 알림(지금 수집 지연 알림과 같은 길).

### P2 오류 알기

- **오류 안내 화면** — "잠시 문제가 생겼어요 · 다시 시도 · 홈으로". 기본 오류 화면 대신.
- **오류 기록** — 어느 화면·언제·무슨 종류만(손님 정보는 담지 않는다). sync-health 가 매일 지난 24시간 오류 수를 보고, 기준을 넘으면 실패로 알린다.

### P3 선불 손님 챙기기

- 챙길 고객 줄에 '선불 52만' 꼬리표 — 디자이너만 본다. 잔액은 추정이라(결제수단이 기록되지 않는다) **손님 문자엔 넣지 않는다.** 같은 상태 안에서는 선불 남은 분을 먼저.
- 통계 요약 카드 '선불 잔액' 아래 한 줄: "3개월 넘게 안 오신 분 N명 · 약 X만" → 누르면 고객 목록(새 필터 '선불 있음').

### P4 쓰이는지 보기 (운영자용)

- 맥에서 돌리는 읽기 전용 점검: 디자이너별 마지막 접속일 · 지난 1주/4주 연락 수(문자·전화·복사) · 그때 챙길 고객 수. 숫자만.
- 이걸로 다음 기능(v4 P3 '내 말투로' 등)을 정한다.

### 개인정보 문서 (결정 필요)

- 처리방침과 위탁 관계(살롱 = 손님 정보의 주인, 운영자 = 맡아서 처리하는 쪽) 초안을 쓰고, 법률 검토는 따로 받는다. 운영자 정보(사업자명·연락처)와 보관 기간을 정해야 한다.

## 2. 하지 않을 것

- **수집을 더 자주** — 약관 리스크로 주 1회 유지(`LAUNCH.md`).
- **외부 오류 감시 서비스 가입**(Sentry 등) — 지금 규모엔 알림 길 하나(sync-health)로 충분하다.
- **잔액을 손님 문자에 넣기** — 추정이라 틀릴 수 있다.
