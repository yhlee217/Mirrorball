> 앱 쪽 다음 큰 일(설치 안내 · 주간 알림)은 다음 주 디자이너 숫자를 보고 정하기로 했다. 그 사이 걸리는 건 **운영자의 손**이다 —
> 다음 주 주환 · 다운부를 매장에 이으려면 지금은 SQL 을 손으로 써야 하고, 테스트 680개는 제 작업 세션에서만 돌며,

## 1. 할 것

### P0 디자이너 연결 한 줄 (맥)
- `worker/link_designer.py <이메일> <매장>` — **미리보기가 기본**, `CONFIRM=1` 이면 연결. 이메일로 계정을 찾고(없으면 '먼저 `/start` 로 로그인해 달라고 하세요'), 매장(slug)을 찾아 소속을 만든다. 이미 이어져 있으면 그대로. 데모 매장 소속은 건드리지 않는다(앱이 실제 매장을 먼저 연다 — v11).
- `--list` — 매장마다 이어진 계정(이메일은 가려서: `j***@g***.com`). 손님 정보는 읽지 않는다.

### P1 푸시마다 자동 검증
- GitHub Actions `test` — 푸시 · 수동 실행 때 타입 검사 + 테스트(브라우저 테스트 포함). 실패하면 GitHub 가 저장소 주인에게 메일(매일 감시와 같은 길).
- 화면 측정(UI 측정)은 글꼴이 다르면 숫자가 흔들려 이 작업 환경에서만 — 자동 검증에선 이유를 남기고 건너뛴다.
- 공개 저장소라 비용 없음, 비밀값(키) 필요 없음.

### P2 운영 안내서 한 장
- `playbook/OPERATIONS_APP.md` — 지금 앱 기준: 매주 흐름(일요일 수집 · 월요일 '새로'), 디자이너 연결 순서(`/start` → 로그인 → 이메일 → `link_designer`), 운영자 폰 · 운영 숫자, SQL 이력(0001~0025 — 무엇을 왜, 실행했는지 확인하는 법), 맥에서 할 일(`git pull` · 백업 · 사용 현황), 문제가 생기면(수집 멈춤 · 화면 오류 · 백업 없음). 앞으로 계획서의 '운영자가 할 일'은 여기에 모은다.

### P3 (확인 뒤) 손님 생일
- 운영자 확인: HandSOS 고객 화면에 생일이 있나(있으면 칸 이름과 모양만 — 손님 정보 없이). 있으면 다음 계획에서 수집 → '이번 주 생일' · 축하 문구(예약 권유 없이, 안부와 같은 결).

### 다음 — 설치 안내 · 주간 알림(다음 주 디자이너 숫자 뒤) · 내 말투로(연락이 쌓이면) · HandSOS 엑셀(운영자 확인 뒤)

## 2. 하지 않을 것
- **앱 화면에서 디자이너 연결** — `/ops` 는 쿠키로만 가린 숫자 화면이다. 쓰기를 열면 누구나 남의 매장에 붙을 수 있다. 연결은 서비스 키가 있는 맥에서만.
- **자동 검증에 비밀값** — 테스트는 키 없이 돈다.
- **화면 측정을 자동 검증에** — 글꼴이 다르면 회색 글자 수 · 첫 화면 줄이 흔들려 거짓 실패가 난다.

## 3. 순서와 확인

P0 → P1 → P2. 단계마다 tsc · 테스트.

| 단계 | 확인할 것 |
|---|---|

| P1 | 첫 실행이 초록(GitHub 기록으로 확인) · 화면 측정만 건너뜀 |
| P2 | 안내서의 명령 · 경로 · SQL 파일이 실제와 같다(정적 검사) |

## 4. 정해야 할 것

1. 디자이너 연결(P0) — **맥 스크립트(추천)** / 지금처럼 Supabase SQL 손작업
2. 자동 검증(P1) — **푸시마다(추천)** / 수동 실행만

4. 생일(P3) — **HandSOS 확인 뒤(추천)** / 안 함
