# 세무 실무자 확인 체크리스트

작성 2026-07-22. 세무 버전 설계 중 **추정으로 남아 있는 것들**.
이 문서를 만든 이유: 제품 방향을 실무 관찰이 아니라 화면 몇 개와 엑셀 한 개로 추정하고 있어서,
틀린 가정 위에 만들면 틀린 걸 만들게 된다. 답을 받으면 이 파일에 바로 적어둘 것.

---

## A. 가장 급한 것 — 방향이 갈리는 질문

### A-1. 야근의 실제 원인
> "한 달 내내 야근"이라고 들었는데, **그 시간에 실제로 뭘 하고 계신가요?**
> 전표 처리인가요, 신고서 작성·검토인가요, 자료 받아내기인가요, 아니면 다른 건가요?

왜 중요한가 — 지금 우리는 "신용카드 미추천 건 처리"를 타깃으로 잡고 있다.
실측해보니 이 작업은 거래처당 월 7건 수준이고, 136곳이면 **월 5시간 정도**로 추산된다.
야근의 주범이 아니라면 방향을 바꿔야 한다.

### A-2. 미처리 규모가 다른 자료에서도 비슷한가
> 통장 / 전자세금계산서 / 현금영수증도 **미추천 비율이 신용카드와 비슷한가요?**

왜 중요한가 — 신용카드만 보면 월 5시간이지만, 4~5종이 다 같은 구조면 월 20~25시간이 된다.
그 차이가 "만들 가치가 있나"를 가른다.
→ **엑셀 3개(통장·세금계산서·현금영수증)만 받으면 우리가 직접 계산 가능.**

### A-3. 자료를 안 주면 실제로 어떻게 처리하나
> 요청한 증빙이 끝내 안 오면 어떻게 하시나요?
> ① 계정을 보수적으로 잡음 ② 가지급금·가수금 처리 ③ 비용 인정 안 함 ④ 불공제 처리 ⑤ 기타

왜 중요한가 — "추측한다"고만 들었는데, 세무에서 증빙 없이 추정 계상하는 건 문제가 된다.
실제 관행이 뭔지에 따라 "미확인 항목"을 시스템이 어떻게 다룰지가 정해진다.

## B. WEHAGO 설정 — 켜면 안 되는 이유가 있는지

### B-1. 거래처 자동생성이 '부'인 이유
> `전표전송 설정 > 미등록 사업자번호 존재 시 거래처 생성`이 **'부'로 되어 있는데 의도한 설정인가요?**

우리가 파악한 사실 — 이걸 '여'로 켜면 신규 가맹점이 자동 등록되고, 등록되면 다음부터
계정과목이 자동 추천된다(실측: 거래처코드 있는 건 69건 중 미추천 1건).

**켜지 말아야 할 이유(우리 추정)** — 거래처 마스터가 오염된다. 신규 가맹점 31곳 중 25곳이
1회성이라, 한 번 가고 마는 식당까지 영구 거래처로 남는다. 되돌리기도 번거롭다.
→ **실무자 확인 없이 건드리지 말 것.**

### B-2. 계정과목 일괄변경을 지금 쓰고 계신가
> 미추천 건을 고칠 때 **하나씩 입력**하시나요, **일괄변경** 기능을 쓰시나요?

왜 중요한가 — 이미 일괄변경으로 빠르게 처리 중이라면 우리 도구의 효과가 줄어든다.

### B-3. 회사 고유 계정과목
> `(제)촬영비`처럼 표준 계정과목표에 없는 계정이 있습니다. **거래처마다 계정과목을 따로 설정하시나요?**

우리가 파악한 사실 — 서식의 표준 코드표에 `촬영비`가 없다. 화면 분개에서는 **528**로 표시됐다.
SmartA10에서 계정과목명을 수정하면 그 회사 코드를 써야 한다고 서식에 명시돼 있다.
→ 계정과목 추천 도구를 만들려면 **거래처별 계정과목표**를 어떻게 얻을지 정해야 한다.

## C. 데이터 반출·반영 — 하지 말아야 할 것 확인

### C-1. 국세청 자료를 지우고 엑셀로 올려도 되나
> 국세청 수집분을 삭제하고 엑셀서식으로 다시 올리는 방식, **신고에 문제가 없을까요?**

우리가 파악한 사실(공식 문서) — 엑셀 업로드분은 `자료구분 = 엑셀`로 **별개 계열**이 된다.
국세청 자료를 대체하지 않는다. 그리고 국세청 공제/불공제 판정은 **수정 불가**로 명시돼 있다.
`수집한 국세청자료집계`·`국세청자료검증및사이트비교`·`공제유형별 집계`가 국세청 자료 기준으로
동작하므로 연결이 끊길 우려가 있다.
→ **결론: 이 방식은 권하지 않음. 실무자가 명확히 문제없다고 하기 전엔 시도 금지.**

### C-2. 카드사 수집 안정성
> 화면 경고 — *"2026.07.08 이후 BC카드 홈페이지 개편으로 일부 매입자료가 누락될 수 있으니
> 수집 내역을 반드시 확인하시기 바랍니다."*
> **지우고 재수집했을 때 카드사 자료가 온전히 다시 들어오나요?**

왜 중요한가 — "필요하면 다시 불러오면 된다"는 전제가 깨지면 데이터를 잃는다.

## E. WEHAGO 자동 다운로드 — 법적 판단 (2026-07-22 확정된 부분)

목표: 수임처별 자료 다운로드를 배치로 자동화 → 받은 자료로 계정과목을 채워 제시.

**확정된 사실:**
- WEHAGO 로그인은 **인증서 아님, ID/PW 기반** → 자동화 기술 난이도 낮음.
- WEHAGO 약관에 **크롤링·스크래핑 명시 금지 조항 없음**(HandSOS 19조1항17호 같은 게 없다).
- 사용하는 계정 = **세무대리인 본인 계정**(직원/사무소 계정 아님). → 5조①(제3자 이용) 무관.
- 개인용·비상업 → 8조①7호(재판매) 무관.

**남는 리스크 = 9조②1호 "서비스에 현저한 지장" 하나뿐.**
→ "현저한 지장"은 결과 요건. 하루 1회·수임처별 자기 자료만·저부하로 돌면 피해 간다.
→ **가드레일: 저부하(요청 간 지연, 영업시간 회피, 하루 1회 상한)로 설계할 것.**

**주의(내가 변호사가 아니라는 전제):** 명시 금지가 없다 = 회색지대가 좁다는 것이지 "허용"은 아니다.
사람이 엑셀변환을 누르는 것(정식 기능)과 프로그램이 자동으로 누르는 것은 법적으로 다르다.
→ 설계는 진행하되, 실서비스 전 **개별약관(WEHAGO T)** 도 한 번 더 확인.

**순서(중요):** 자동 다운로드는 마지막에. 먼저 분류 엔진 + 공용 사전이 실제로 쓸모 있는지
증명(엑셀 몇 개로) → 되면 저부하 다운로드로 감싼다. 엔진이 별로면 다운로드는 의미 없다.

## D. 참고 — 이미 확인된 사실 (다시 묻지 말 것)

- **미추천의 정의**(공식 문서): 거래처+품명 분석으로 추천율 50% 초과인 계정을 추천.
  거래내역이 없거나 추천율 50% 이하면 '미추천'. 흰색=100%, 주황=51% 이상.
- **실측(비커뮤니케이션즈 2026 상반기 신용카드 매입 150건)**
  - 미추천 40건(26%). Code 있음 69건 중 미추천 1건 / Code 없음 81건 중 39건.
  - 가맹점(사업자번호) 기준 계정 예측 적중률 **97%**, 종목 기준 **61%**.
  - 미추천 40건은 **전부 과거 이력이 없는 신규 가맹점**. 고유 31곳, 그중 1회성 25곳.
  - 체인점 정규화로 커버 가능한 곳 8/31(25%). 나머지는 개인 음식점이라 타 거래처 이력에도 없을 것.
  - 같은 종목이 갈리는 사례: 커피 전문점 → 촬영비 7 : 접대비 8 / 편의점 → 촬영비 5 : 소모품비 5.
    **누구와 갔는지가 영수증에 없어 데이터만으로는 판정 불가.**
- **이미 WEHAGO에 있는 기능**(중복 개발 금지): 휴폐업조회, 오류검증, 공제유형별 집계,
  부가세신고요약, 고정자산 확인(300만원 이상), 면세확인, 세액확인, 전자중복, 체크카드 감지.
- **엑셀 왕복 경로**: `조회한 데이터를 엑셀로 변환`(반출) / `매입엑셀서식 내려받기·불러오기`(반입).
  서식 컬럼 13개 — 거래일자·거래처(가맹점명)·사업자번호·품명·유형·공급가액·세액·봉사료·합계·
  차변계정코드·대변계정코드·공제여부·거래구분. **업태·종목·거래처코드는 서식에 없음.**
