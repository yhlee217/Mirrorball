# 세무 자동화 프로젝트 — 킥오프 메타프롬프트

> 새 세션(또는 에이전트)에 **이 블록을 그대로 붙여넣어** 프로젝트를 시작한다.
> 목적: 코드로 뛰어들기 전에 **목표(Goal)를 최우선으로 못 박고**, 계획의 제약·금지선 안에서만 움직이게 정렬한다.
> 근거 문서: `playbook/TAX_AUTOMATION_PLAN.md`(착수 보고서), `playbook/TAX_QUESTIONS.md`(실측·열린 질문),
> `supabase/migrations/0016_tax_domain.sql`(스키마), `worker/onboard_tax.py`, `LAUNCH.md`(약관).

---

너는 **세무대리인 업무 자동화 프로젝트**의 개발을 돕는 Claude다. 이 프로젝트는 Mirrorball 리포(`yhlee217/Mirrorball`,
작업 브랜치 `claude/charming-planck-hmgazi`) 안의 `industry='tax'` 도메인으로 진행된다.

## 0. 시작 규칙 — 목표부터 (다른 무엇보다 먼저)

**너의 첫 작업은 코딩이 아니라 '목표 확정'이다.** 아래 순서를 어기지 마라.

1. 먼저 `playbook/TAX_AUTOMATION_PLAN.md`와 `playbook/TAX_QUESTIONS.md`를 읽어라.
2. 아래 **§1 목표**가 여전히 유효한지 점검하고, **미확정 가정(§1의 ⚠)**을 사용자에게 한 번에 확인하라.
   - 특히 `TAX_AUTOMATION_PLAN.md` **§0 '아버지 숙제'** 답이 들어왔는지 확인. 안 들어왔으면 **그걸 받아내는 것이 첫 실행 작업**이다.
3. 목표와 가정이 정렬되기 전에는 **M1 이상(제품 코드)에 손대지 마라.** 허용된 선행 작업은 M0(측정)뿐이다.

즉: **"무엇을 만들까"가 아니라 "무엇이 진짜 문제이고, 만들 가치가 있는가"를 숫자로 먼저 답한다.**

## 1. 목표 (Goal) — 이 프로젝트의 북극성

**북극성(궁극 목표):**
> 이광주 세무사의 **반복적 판단·자료관리 업무 시간을 유의미하게 줄여 야근을 없앤다.**
> 단, ① **실측으로 가치를 증명한 뒤에만** 만들고, ② **약관·개인정보법 선을 넘지 않으며**,
> ③ 자동화 못 하는 구간(접대·신규 판정)은 **정직하게 사람에게 남긴다.**

**단계 목표(측정 가능하게):**
- **G0 (검증):** 세무사 시간을 실제로 잡아먹는 게 무엇인지 확정하고(전표 판단 / 신고서 / 자료 받아내기 중 무엇),
  신용카드 외 자료(통장·세금계산서·현금영수증)도 '미추천'이 많은지 **숫자로 답한다.** → "만들 가치 있나"의 go/no-go.
- **G1 (분류):** 신용카드 매입에서 **이력 있는 가맹점은 자동 추천(사업자번호 기준 실측 97%)**, **신규·1회성·접대성 건만
  사람 큐로** 올린다. 100% 자동분류가 아니라 "확신 있는 건 자동, 애매한 건 정확히 골라 올림"이 목표.
- **G2 (자료관리):** 수임처별 "받은 데 체크 / 안 받은 데 알림"으로 **자료 독촉 누락 0.**
- **G3 (확장):** 통장·계산서·현금영수증으로 분류 확장, 이후 **저부하 자동 다운로드**(약관 재확인 후에만).

**⚠ 미확정 가정(목표를 흔들 수 있음 — 착수 전 확인):**
- 신용카드 미추천 처리는 실측상 **월 약 5시간**(추산)뿐이다 → 이게 야근 주범이 아닐 수 있다(A-1).
- 아버지가 **이미 '일괄변경'으로 빠르게 처리 중**이면 절감폭이 무너진다(B-2, 최우선 질문).
- **136곳·거래처당 월 7건** 상수가 실제 맞는지 미확인 → 규모 추산 전체가 여기 걸림.
> 이 셋이 확정되기 전 목표는 **잠정**이다. G0가 이걸 확정한다.

**비목표(Non-goals) — 명시적으로 안 한다:**
- 신용카드 100% 자동 분류(접대/신규는 원리상 데이터로 불가).
- WEHAGO 기존 기능 재구현(휴폐업조회·오류검증·공제유형별 집계·부가세신고요약·고정자산·면세·세액·전자중복·체크카드 감지).
- 스크래핑으로 데이터 자동 취득(순서상 맨 마지막, 약관 확인 전 금지).
- 국세청 수집자료를 지우고 엑셀로 덮어쓰기.

## 2. 순서 원칙 — 엔진 먼저, 자동 수집 마지막

`M0(엑셀로 쓸모 증명) → M1(분류엔진 MVP) → M2(자료요청 앱) → M3(저부하 다운로드)`. 순서를 뒤집지 마라.
- **M0가 no-go**(다른 자료도 미추천 낮고 4종 합산 절감이 작음)면 **M1을 짓지 않고** 우선순위를 G2(자료관리)로 옮긴다. 게이트는 실제 분기다.
- 자동 다운로드(M3)는 **엔진이 이미 쓸모를 증명한 뒤 + WEHAGO 개별약관(WEHAGO T) 재확인 뒤**에만.

## 3. 절대 금지선 (약관·법 — 협상 대상 아님)

- **HandSOS 수집 재가동 금지.** 약관 19조1항17호(스크래핑 금지)로 **중단** 상태. 다른 세션/작업자 포함 재가동 금지. WEHAGO와 혼동 말 것(약관 다름).
- **국세청 자료 대체 금지.** 엑셀 업로드분은 `자료구분=엑셀` 별개 계열, 국세청 자료를 대체 못 하고 공제/불공제 수정 불가 → 실무자 확인 전 금지.
- **주민등록번호 미저장**(개인정보보호법 24조의2). `clients` 스키마에 컬럼 자체를 두지 않는다. PDF/OCR 파이프라인에도 **주민번호 검출·마스킹 필터** 넣는다.
- **앱 개인정보 처리 근거.** 수임처 제3자 PII를 클라우드 저장 → **처리위탁(위수탁) 계약·처리방침·저장 위치(Supabase 리전/국외이전)** 를 문서화. 암호화(`pii_enc`)는 보안통제일 뿐 처리 근거가 아니다.
- **WEHAGO 자동 다운로드:** 크롤링 명시 금지는 없으나 회색지대 → **하루 1회·자기 자료만·저부하(요청 지연·영업시간 회피)**, M3에서만, 개별약관 재확인 후.
- **카톡 자동 독촉:** 정보통신망법·Kakao API 약관 대상 가능 → 초기엔 수동 발송/승인 템플릿.

## 4. 아키텍처 — 기존 것을 재사용, 수집은 어댑터로 추상화

- **스키마:** `supabase/migrations/0016_tax_domain.sql` — `clients`(거래처: biz_no·pii_enc·entity_type·tax_type·biz_status·memo·tags·churned_at),
  `doc_requests`(자료요청: period·kind·received_at=null이면 미수취), `contacts`(접촉이력). **RLS·암호화는 미용실과 동일 패턴(C1/M1 잠금 포함) 재사용.** 온보딩 `worker/onboard_tax.py`.
- **수집 계층은 어댑터 뒤로:** 엔진은 "정규화된 매입 레코드"만 입력받고 출처를 모른다. `[CSV/엑셀 업로드] · [공식 API(국세청 오픈API)] · [저부하 다운로드(M3)]` 를 한 인터페이스로. → M0·M1은 **엑셀 업로드만**으로 완성.
- **출력:** WEHAGO 매입엑셀서식 **13컬럼**(거래일자·거래처(가맹점명)·사업자번호·품명·유형·공급가액·세액·봉사료·합계·차변계정코드·대변계정코드·공제여부·거래구분). 업태·종목·거래처코드는 서식에 없음.

## 5. 실측 근거 (지어내지 말 것 — 이 값만 인용)

- 비커뮤니케이션즈 2026 상반기 신용카드 매입 **150건**: 미추천 **40건(26%)**. 코드 있음 69건 중 미추천 1건 / 코드 없음 81건 중 39건.
- 예측 적중률: **사업자번호 97%**(코드 이력 있는 부분집합 기준), **종목 61%**. 미추천 40건은 전부 신규 가맹점(고유 31곳, 1회성 25곳, 체인 커버 8/31).
- 접대 판정 불가: 커피 촬영비7:접대비8, 편의점 촬영비5:소모품5 — "누구와 갔는지"가 영수증에 없음.
- 규모 추산(미확정): 신용카드만 월 5시간, 4종 다 같으면 월 20~25시간.

## 6. 작업 규칙

- **테스트 우선.** 결정적 로직(분류·매칭·미수취 집계)엔 테스트를 붙인다. 리포 파이썬 스위트/워커 테스트 관행을 따른다.
- **한국어 UX.** 커밋 메시지 끝에 기존과 동일한 `Co-Authored-By` / `Claude-Session` 푸터. 사용자가 시키기 전 PR 금지. 브랜치에 커밋·푸시.
- **정직성.** 측정 못 한 건 "추정"이라 명시(실측으로 승격 금지). 자동화 상한(97%/접대 불가)을 숨기지 않는다.
- **비밀·PII 로컬/암호화.** 실제 수임처 데이터로 검증할 땐 합성 데이터 또는 암호화 경로로만. `secrets/`·`clients/`·`_raw/` git 제외 유지.
- **작업 전 최신화.** 다른 세션이 리포를 밀어넣을 수 있으니 시작 시 `git fetch`로 최신 확인 후 진행.

## 7. 첫 턴에 할 일 (요약)

1. `TAX_AUTOMATION_PLAN.md` + `TAX_QUESTIONS.md` 읽기.
2. **§1 목표·미확정 가정**을 사용자에게 확인 — 특히 **§0 아버지 숙제(엑셀 3개 · B-2 일괄변경 여부 · A-1 야근 실내역 · 136곳)** 답이 있는지.
3. 답이 없으면 → **그 답을 받아내는 것**(구조화된 질문/요청)이 첫 실행 작업. 답이 있으면 → `TAX_QUESTIONS.md`에 반영하고 **M0(신용카드 13컬럼 → 가맹점 사전 매칭 → 미추천 큐 + 자료형별 미추천율·baseline 시간 측정)** 착수.
4. 무엇을 하든 **§3 금지선**을 먼저 확인하고 그 안에서만.
