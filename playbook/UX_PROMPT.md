## 0. 누가 · 언제 · 어떻게 쓰는가 (이걸 벗어난 개선은 개선이 아니다)

- **사용자**: 미용실 디자이너 3명(대표: 살롱톤). 개발자도 데이터 분석가도 아니다.
- **기기**: **휴대폰 한 손**. PWA 로 설치해 쓴다. 데스크톱은 사실상 안 쓴다.
- **상황**: 손님 응대 **사이사이 몇 초**. 앉아서 들여다보는 도구가 아니다.
- **데이터는 주 1회(일요일 14:00) 갱신된다.** 실시간이 아니다. 화면은 항상 며칠 전 상태이고,
  그 사실을 숨기면 "예약이 없다"를 지금의 사실로 오해한다.

→ 판단 기준: **"손님 앞에서 3초 안에 답이 나오는가."** 정보를 더 넣는 쪽이 아니라
   덜어내고 순서를 바꾸는 쪽을 먼저 검토하라.

## 1. 이미 정해진 것 (되돌리지 말 것 — 이유가 있다)

- **홈은 고객관리가 주역**이다. 신호 4타일(이탈위험·재방문도래·신규·VIP) → 챙길 고객 →
  방문관리 순. **예약은 맨 아래**로 내렸다. 주 1회 수집이라 최대 7일 묵어 오해를 부르기 때문.
- **모든 화면에 '수집 기준일'을 밝힌다**(`lib/sync.ts` 의 `syncLine`). 10일 넘으면 "수집이 밀렸어요".
- **추정은 추정이라고 쓴다.** 선불 잔액, 성별, AI 메모 정리 모두 추정이며 화면에 근거와
  판정률을 함께 보여준다. 확정처럼 보이게 만들지 마라.
- **되묻지 않고 현재 상태를 서술한다.** 예: 선불 토글은 `사비?`(질문)가 아니라
  `잔액 차감`(현재 상태) → 누르면 `사비 결제`. 같은 원칙을 새 컨트롤에도 적용하라.
- **강요하지 않는다.** 리뷰 요청 복사 버튼은 종용처럼 보여 뺐다. 홈케어 팁도 줄마다 펼치지
  않고 우측 상단 표식으로 접었다.
- 이름은 테넌트 키로 암호화 저장되고 화면 렌더 순간에만 복호화된다. 클라이언트로 키가 안 간다.

## 2. 지금 알려진 UX 부채 (실측·사용자 피드백 기반)

1. **성별 미상 고객을 한 번에 훑을 방법이 없다.** 미상이 daunbu 363 · hayewoni 272 ·
   juhwan 305명인데, 채우려면 카르테를 하나씩 열어야 한다. → 고객 목록 필터 또는 전용 화면.
2. **카르테가 길다**(371줄 렌더). 한눈에·신호·이탈토글·성별·통계·가족·예약·선불·메모·시술이력이
   세로로 쌓인다. 손님 앞에서 스크롤을 얼마나 하는지 따져보고 우선순위를 다시 잡아라.
3. **탭 라벨 '알림'** — 실시간 푸시가 아니라 주간 목록이다. 이름이 기대를 어긋나게 한다.
4. **통계 화면이 숫자 나열에 가깝다.** 무엇을 해야 하는지로 연결되지 않는다.
5. 빈 상태·에러 문구가 화면마다 다르다. (`지금 챙길 고객이 없어요` / `조건에 맞는 고객이 없어요` …)

## 3. 디자인 제약

- **기존 디자인 토큰을 쓴다** — `web/app/globals.css` 상단의 `--accent`(#6E5B47) ·
  `--gold` · `--sage` · `--rose` · `--soft` · `--line`. 새 색을 함부로 늘리지 마라.
  이 팔레트는 살롱 톤(따뜻한 브라운)이고 이미 전 화면이 여기 맞춰져 있다.
- 한 손 조작: 주요 동작은 **엄지 닿는 아래쪽**. 탭 타깃은 충분히 크게.
- 접근성: 색만으로 의미를 전하지 말 것(이미 `이탈 위험` 같은 라벨을 함께 쓴다).
  `aria-pressed`·`aria-label` 을 토글에 유지하라.
- 애니메이션은 절제. `prefers-reduced-motion` 존중.

## 4. 작업 규칙

- **한 번에 한 화면**씩. 바꾸기 전에 "지금 이 화면에서 무엇이 몇 초 걸리는지"를 말로 정리하고,
  바꾼 뒤 그게 줄었는지로 자평하라.
- 문구는 **사용자의 말**로. 시스템 용어(테넌트·업서트·ext_id)를 화면에 노출하지 마라.
- 변경 후 `cd web && npx tsc --noEmit` 통과 필수. 서버/클라이언트 컴포넌트 경계를 지킬 것
  (데이터 조회는 서버, 상호작용만 `'use client'`).
- 사용자 값이 바뀌는 컨트롤은 저장 후 `router.refresh()` 로 서버 계산값을 다시 그려라
  (선불 토글에서 이걸 빠뜨려 잔액이 안 바뀌는 버그가 났다).
- 사용자가 시키기 전 PR 금지.

## 5. 첫 턴에 할 일

1. `git fetch` 로 최신 확인.
2. 실제 화면 파일을 읽어라 — `web/app/page.tsx`(홈) · `customers/` · `customer/[id]/` ·
   `visits/` · `alerts/` · `stats/`. 추측하지 말 것.
3. §2 목록 중 **어디부터 손댈지 사용자에게 제안**하라. 추천은 1번(성별 미상 훑기) —
   지금 사용자가 실제로 막혀 있는 작업이고 범위가 작다.
4. 화면을 바꾸기 전에 **바뀐 뒤 모습을 말로 먼저 그려** 확인받아라.
