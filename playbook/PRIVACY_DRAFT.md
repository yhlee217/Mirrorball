# 개인정보 처리 — 초안 (법률 검토 전 · 앱에 게시하지 않음)

> 개선 계획 v5 결정 4: 초안을 쓰고 검토는 따로 받는다. 이 문서는 **법률 자문이 아니다** — 개인정보보호법(PIPA)에 맞는지 전문가(변호사·개인정보 전문 노무/컨설팅) 검토를 받은 뒤 게시한다. `[ ]` 는 운영자가 채울 칸이다.
> 근거: 코드 실사(2026-10-12). 실제와 다르면 문서를 고친다 — 처리방침은 '실제로 하는 일'을 그대로 적는 문서다.

## 0. 누가 무엇인가

| 역할 | 누구 | 하는 일 |
|---|---|---|
| **개인정보처리자**(손님 정보의 주인) | 각 매장(살롱·디자이너) | 손님 정보를 모으고 쓰는 주체. 손님에게 처리방침을 알린다 |
| **수탁자**(맡아서 처리) | Mirrorball 운영자 `[사업자명]` | 매장의 위탁을 받아 손님 정보를 보관·정리해 매장에 보여준다 |
| 재수탁(인프라) | Supabase(DB) · Cloudflare(웹) · Anthropic(메모 요약) | 운영자가 쓰는 서비스 — 매장의 사전 동의·공개가 필요하다(§2-6) |

그래서 문서가 둘이다: **① 매장과 운영자의 위탁 계약**(§1), **② 처리방침**(§2 — 매장의 처리방침에 들어갈 '위탁' 항목 + 디자이너 계정에 대한 운영자 자신의 방침).

## 1. 위탁 계약에 들어갈 것 (개인정보보호법 제26조)

- [ ] 위탁 업무의 목적·범위 — 재방문 관리 · 예약 준비 · 매장 통계를 위한 손님 기록의 보관·정리·표시
- [ ] 목적 외 처리 금지 — 다른 매장과 섞지 않는다(매장별 접근 통제), 영업·광고에 쓰지 않는다
- [ ] 기술적·관리적 보호조치(§2-7을 그대로)
- [ ] 재위탁 제한 — 지금 재수탁자 목록(§2-6) 명시, 바꿀 때 매장에 미리 알림·동의
- [ ] 관리·감독 — 매장이 요청하면 처리 현황·보호조치를 보여준다
- [ ] 사고 시 통지 — 유출을 알게 되면 `[ ]`시간 안에 매장에 알림
- [ ] 손해배상 책임
- [ ] 위탁이 끝나면 — `[ ]`일 안에 손님 정보 파기(DB 와 백업 모두), 원하면 먼저 내보내기(CSV) 제공
- [ ] 수집 근거 — 매장이 쓰는 예약·매출 관리 프로그램(POS)의 **매장 계정**으로 매장 기록을 가져오는 것을 매장이 위임한다는 문구. ⚠ POS 이용약관과의 관계는 `LAUNCH.md` 리스크 메모와 함께 검토받는다

## 2. 처리방침 초안

### 2-1. 처리하는 개인정보

| 대상 | 항목 | 비고 |
|---|---|---|
| 매장 손님 | 이름 · 전화번호 | **매장별 키로 암호화**(AES-256-GCM)해 저장 — DB 에 평문 없음 |
| 매장 손님 | 방문일 · 시술 · 금액 · 선불 충전·사용(추정 잔액) · 예약 일시 | 매장 POS 기록 |
| 매장 손님 | 매장 메모 · 취향 태그 · 메모 요약 · 성별(시술명 추정 또는 디자이너 지정) · 연락 기록(문자·전화·복사한 시각) · 이탈 표시 | 디자이너가 앱에서 남기거나 앱이 정리한 것. 메모는 평문 — `[암호화 여부 검토]` |
| 디자이너(앱 이용자) | 이메일 · 로그인 기록 | 운영자가 직접 처리(운영자가 처리자) |

### 2-2. 목적
재방문 시기 안내와 연락 준비 · 예약 전 손님 기록 확인 · 매장 매출·방문 통계. 그 밖의 목적(광고·판매·다른 매장 공유)으로 쓰지 않는다.

### 2-3. 수집 방법
매장이 쓰는 예약·매출 관리 프로그램(POS)의 매장 기록을 매장 요청으로 주 1회 가져온다 · 디자이너가 앱에서 직접 입력한다.

### 2-4. 보관 기간
매장이 서비스를 쓰는 동안. 위탁이 끝나면 `[ ]`일 안에 파기한다. 주 1회 백업은 8주가 지나면 자동으로 지워진다(`worker/backup.py`).

### 2-5. 제3자 제공
없다.

### 2-6. 처리 위탁(재위탁)과 국외 이전 — `[검토 필요]`

| 받는 곳 | 하는 일 | 나라 | 넘어가는 것 |
|---|---|---|---|
| Supabase | 데이터베이스 · 로그인 | `[프로젝트 리전 확인]` | §2-1 전부(이름·전화는 암호문) |
| Cloudflare | 웹 화면 제공 | 전 세계(가까운 서버) | 화면을 그리는 동안 지나가는 데이터 |
| Anthropic | 매장 메모 요약 | 미국 | 날짜와 메모 문장만(이름·전화는 보내지 않는다 — `worker/summarize_memos.py`). 메모에 건강·생활 이야기가 있을 수 있어 고지가 필요한지 검토 |

국외 이전이면 이전 항목·국가·시기·방법·보유 기간·거부 방법을 적어야 한다(제28조의8) — 검토자에게 확인.

### 2-7. 안전성 확보 조치(지금 하고 있는 것)
- 이름·전화 암호화(매장별 키, 마스터 키로 다시 감쌈) · 키 교체 절차(`playbook/KEY_ROTATION.md`)
- 매장별 접근 통제(DB 행 수준 보안 — 다른 매장 기록은 조회 자체가 안 된다)
- 전송 구간 암호화(HTTPS)
- 주 1회 암호화 백업(8주 보관) · 수집·백업·화면 오류 매일 감시(손님 정보는 감시 기록에 남기지 않는다)
- 화면 오류 기록에는 화면 경로(손님 id 는 지움)와 오류 번호만

### 2-8. 손님의 권리
손님은 매장을 통해 열람·정정·삭제·처리 정지를 요청할 수 있다. 매장이 운영자에게 알리면 `[ ]`일 안에 처리한다(고객 CSV 내보내기·카르테 수정·삭제).

### 2-9. 문의
개인정보 보호책임자: `[이름 · 연락처 · 이메일]`

## 3. 운영자가 정할 것

1. 사업자명 · 보호책임자 · 연락처
2. 위탁이 끝난 뒤 파기 기한(예: 30일)
3. Supabase 프로젝트 리전(대시보드 → 프로젝트 설정에서 확인)
4. 메모 요약(Anthropic) 고지 방식 — 매장 처리방침에 넣을지, 메모 요약을 끌 수 있게 할지
5. 메모(평문)를 암호화할지 — 지금은 검색·요약을 위해 평문
6. 검토받을 곳

검토가 끝나면: 앱에 `/privacy` 화면을 만들고 로그인 화면·설정·공개 소개 페이지(`/p/...`) 아래에 링크한다.
