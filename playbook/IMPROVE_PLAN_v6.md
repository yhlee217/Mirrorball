## 1. 할 것

### P0 수집 사이 다녀가신 분 — 목록에서 빼기

- 마지막 수집일 ~ 지금 사이에 예약이 있었고(취소 · 노쇼 아님) 그 시각이 지났으면 **'다녀가셨을 분'**으로 보고 챙길 고객 · 홈 숫자 · 이탈위험/재방문도래 숫자 · 카르테 뱃지에서 뺀다. 다음 수집이 방문(또는 노쇼)을 잡으면 저절로 맞춰진다.
- 고객 목록 '예약 있음'은 지금처럼 **앞으로 올 예약만** — 뜻이 달라 판정을 둘로 나눈다(표시용 / 챙길 고객 제외용).
- 카르테 '다음' 칸: 예약일이 지났으면 '10.15 예약 · 수집 전'(다녀가셨는지는 일요일 수집 뒤에 안다).
- 연락 효과의 '예약'도 같은 판정으로 — 연락 뒤 예약하고 다녀가신 분이 수집 전까지 '효과 없음'으로 빠지지 않게.
- 노쇼였다면 다음 수집 뒤에 다시 오른다(최대 한 주 늦게) — 어제 오신 분께 문자하는 실수보다 낫다.
- 점검 스크립트(`ux_probe`)도 같은 규칙, 웹과 대조 테스트(휴가 · 첫 방문 때와 같은 방식).

### P1 폰에서 남은 어색한 곳

- 통계 할 일 알약 — 홈과 같은 모양(한 줄을 고르게, 안 들어가면 첫 알약이 윗줄 · 나머지 둘이 아랫줄 반씩).
- 한국어 줄바꿈 — 어절 단위로 끊고(`word-break: keep-all`), 띄어쓰기 없는 긴 말(시술명 '뿌리염색+커트+클리닉' 등)만 어디서든 끊어 넘치지 않게. 360px '넘침 · 잘림 0' 측정 유지.
- 같은 말 같은 글자 — '이탈 위험 · 재방문 도래'로 맞춘다(띄어 쓴 쪽이 더 많이 쓰이고 읽기 쉽다). 알약 폭은 측정으로 확인.

### P2 매주 다시 열게 — 주간 알림 (사용 측정 뒤)

- 수집 뒤 첫 영업일 아침(설정의 휴무를 따른다)에 한 줄: **"이번 주 챙길 고객 84명 · 새로 12명"**. 손님 이름 · 번호 · 시술은 넣지 않는다(잠금 화면에 보인다).
- 디자이너가 설정에서 켠다(아이폰은 홈 화면 앱 + iOS 16.4 이상). 끄면 그 주부터 안 간다.
- 챙길 고객에 **'새로'** 표시 — 이번 수집으로 처음 오른 분(재방문 시기가 이번 주에 된 분 · 이번 주 첫 방문 · 연락 2주가 지나 다시 오른 분). 알림을 안 켜도 '어디서부터 보면 되나'가 보인다.
- 보내는 곳은 맥(서비스 키를 이미 가진 곳). 숫자는 점검 스크립트와 같은 규칙(이미 웹과 대조 테스트).
- 운영자 할 일: 마이그레이션 1개(알림 구독 표) 실행 + 알림 키 한 쌍 등록(맥 `.env` · Cloudflare). 키 값은 채팅에 붙이지 않는다.

### P3 내 말투로 (v4 P3 — 사용 측정 뒤)

- 설정 '문구' 카드 — 종류별(안부 · 다시 오실 때 · 재방문 · 오랜만) 틀을 디자이너가 고친다. {이름} · {시술} · {기간} · {팁} + 미리보기. 비우면 지금 문구.
- 문자 버튼을 주에 몇 번 누르는지 보고 정한다 — 거의 안 쓰면 P2(다시 열게)가 먼저다.

### P4 수집 대안 (Plan B) — 확인부터

- 운영자가 HandSOS 화면에서 **내보내기(엑셀)**가 되는 것을 확인: 고객 목록 · 매출(시술) 내역 · 예약.
- 되면 맥에서 그 파일을 읽어 지금과 같은 표에 넣는 가져오기 스크립트 — 수집 쪽만 바꾸고 앱은 그대로. 한 주는 수집과 나란히 돌려 결과가 같은지 본다.
- 안 되면 지금처럼 주 1회 수집, 확인 결과만 `LAUNCH.md`에 남긴다.

## 2. 하지 않을 것

- **수집을 더 자주** — 약관 리스크로 주 1회 유지(`LAUNCH.md`). P0 은 수집을 늘리지 않고 '이미 잡혀 있던 예약'으로 메운다.
- **알림에 손님 정보** — 이름 · 번호 · 시술은 넣지 않는다.
- **알림을 매일** — 수집이 주 1회라 매일 보낼 새 소식이 없다.
- **자동 발송** — 문자는 늘 디자이너 손에서.

## 3. 시작 전에 잴 것

v5 사용 현황 점검을 맥에서 한 번(읽기 전용, 이름 · 이메일 없음):

```bash
cd ~/Dev/Mirrorball && git pull origin claude/charming-planck-hmgazi && .venv/bin/python worker/usage_probe.py
```

| 재는 것 | 정하는 것 |
|---|---|
| 디자이너별 마지막 접속 | P2 — 일주일 넘게 안 여는 분이 있으면 알림이 먼저 |
| 지난 1주/4주 연락 수(문자 · 전화 · 복사) | P3 — 문자를 꾸준히 쓰면 '내 말투로' |
| 그때 챙길 고객 수 | 알림 문구의 숫자 감 |

그리고 HandSOS 내보내기 확인(P4) — 운영자가 화면에서. **P0 · P1 은 측정 없이 바로 시작할 수 있다.**

## 4. 순서와 확인

P0 → P1 → (측정 결과) → P2 · P3 → P4. 단계마다 tsc · 테스트 · Pages 빌드 · UI 측정(`sh web/scripts/ui-audit/run.sh --check`).

| 단계 | 확인할 것 |
|---|---|
| P0 | 일요일 수집 · 화요일 예약 → 수요일에 목록 밖 · 다음 수집에 방문이 잡히면 그대로 밖 · 노쇼면 다시 안 · 고객 목록 '예약 있음'은 앞으로 올 예약만 · 웹과 점검 스크립트가 같은 수(테스트) |
| P1 | 통계 알약 390px 한 줄 · 360px 하나만 떨어짐 0 · 넘침 · 잘림 0 · 다른 표기 0곳 |
| P2 | 알림에 이름 · 번호 없음(테스트) · 끈 분께 안 감 · 알림 숫자 = 화면 숫자 |
| P3 | 틀을 비우면 지금 문구 · 미리보기 = 실제 문자 |
| P4 | 내보낸 파일로 넣은 결과 = 같은 주 수집 결과 |

## 5. 정해야 할 것

1. 수집 사이 지난 예약(P0) — **다녀가셨다고 보고 다음 수집까지 뺀다(추천)** / 그대로 둔다
2. 표기(P1) — **'이탈 위험 · 재방문 도래'(띄어 씀, 추천)** / '이탈위험 · 재방문도래'
3. 주간 알림(P2) — **측정 보고 정한다(추천)** / 바로 만든다 / 하지 않는다
4. 내 말투로(P3) — **측정 보고 정한다(추천)** / 바로 만든다
5. 수집 대안(P4) — **HandSOS 내보내기 확인부터(추천)** / 보류
