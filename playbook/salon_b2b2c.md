# 실행 문서 ③ — 살롱 단위 B2B2C

> 디자이너 1명씩이 아니라 **살롱(원장)과 한 번 계약해 소속 전원을 일괄**.
> 영업비용(CAC)을 1/N로 줄이고 객단가를 키운다.

## 왜 살롱 단위인가

- **CAC 급감**: 1번 영업으로 5~15명 확보 (개인 1명씩 설득 대비 압도적).
- **신뢰 점프**: 원장 추천이 곧 보증 → 디자이너 개별 설득 불필요.
- **운영 효율**: `build.py --all` 로 소속 전원 한 번에 빌드·발행 (이미 지원).

## 타깃 살롱 선정

- 개인 영업(④) 중 **같은 살롱에서 2명 이상이 반응**하면 그 살롱이 1순위.
- 규모: 디자이너 **5~15명**(너무 크면 의사결정 느림, 너무 작으면 효과 적음).
- 원장이 마케팅에 관심 있고, 소속 디자이너 이탈을 걱정하는 살롱.

## 제안 구조 (원장 대상 Pitch)

1. **현황 보여주기**: 살롱 주력 키워드로 `compete.py` → *"이 살롱은 AI 검색에서 거의 안 나오고, 경쟁 매장이 노출됩니다."*
2. **그림 제시**: 소속 전원 프로필 + 살롱 공통 페이지 + 분기 노출 리포트(살롱 단위 성과 가시화).
3. **이직 우려 차단**: *"프로필·데이터는 디자이너 개인 귀속이라, 누가 들어오고 나가도 살롱 간판은 유지됩니다."*

## 패키지·가격 (예시)

| 항목 | 내용 | 가격 |
|---|---|---|
| 살롱 셋업 | 소속 전원 프로필 제작 + 살롱 페이지 | 1인당 **12만** (개인 15만 대비 할인) |
| 살롱 Pro | 분기 살롱 노출 리포트 + 인당 월 콘텐츠 | 1인당 **월 3만** (개인 4만 대비 할인) |
| 최소 계약 | 디자이너 3명 이상 | — |

→ 예: 8명 살롱 = 셋업 96만(1회) + 월 24만(Pro). **한 건으로 개인 8건치 매출.**

## 운영 팁

- 입력: `designers/{salon}_{name}.yaml` 컨벤션으로 모아두고 `python build.py --all`.
- 데이터 귀속: 계약서에 **"디자이너 프로필·후기 데이터는 개인 소유, 이직 시 이관 가능"** 명시 → 디자이너도 안심, 살롱도 OK.
- 살롱 공통 페이지엔 소속 디자이너 링크를 모아 — 살롱 자체 SEO·AI 노출도 같이 올라간다.

## 주의

- **의사결정이 느리다**: 원장 1명만 설득하면 되지만 시간이 걸림 → 개인 영업(④)을 병행해 현금흐름 유지.
- **이탈 리스크**: 디자이너가 나가면 매출 빠짐 → 데이터 개인 귀속 + 디자이너 개별 만족도 관리로 방어.
- 너무 큰 프랜차이즈는 본사 의사결정 → 그건 **화이트라벨(⑨)** 로 따로 접근.
