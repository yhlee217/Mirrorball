# 자료 요청서 — 원장님이 채워서 주실 것

> 아래만 채워주시면, 빌드·루프·발행물(프로필·카드·콘텐츠·진단 리포트)은 제가 전부 만듭니다.
> **티어 1만으로도 바로 결과가 나옵니다.** 2·3은 품질·범위를 올리는 용입니다.
> 형식은 그대로 복붙해서 빈칸([ ])만 바꿔 주세요. 모르면 비워두셔도 됩니다(경고만 뜨고 진행).

## 무엇을 주면 → 무엇이 나오나

| 주실 자료 | 나오는 것 |
|---|---|
| ① 디자이너 기본 정보 | 호스팅 프로필 페이지(`dist/{slug}/index.html`) + JSON-LD/SEO |
| ② 손님이 AI에 물을 질문 10개 | AI 노출 진단 리포트 + 경쟁 스캔 |
| ③ API 키(선택) | ②를 무인 자동 실행 |
| ④ 검증된 영업 노하우 | 카피 엔진 품질↑(KB) — "잘 파는 카피" 자동 생성 |
| ⑤ 5점 정답 카피 | 루프의 품질 기준선 상승 |
| ⑥ 메뉴·후기·전후사진(선택) | 프로필에 메뉴판·후기·전후 갤러리 + 손님 카드 |

# 티어 1 — 지금 당장 (이것만 주면 발행·진단 시작)

## 1-A. 디자이너 기본 정보 (1명당 1개)

```yaml
slug: [영문소문자_식별자 예: kimminji]
display_name: "[영문 표기 예: Minji]"
korean_name: "[한글, 자간 띄움 예: 김 민 지]"
role: "[예: 헤어디자이너]"
salon: "[매장명 예: 살롱드헤어 강남점]"
region: "[지역 예: 강남역]"
instagram: "[인스타 핸들만 예: minji.hair]"
booking_url: "[네이버 예약 등 URL, 없으면 비움]"
photo_url: "[프로필 사진 URL, 없으면 비움 → 이니셜 표시]"
tagline: |
  [한두 줄 소개. 예: 결을 살리는 컬러와 자연스러운 펌.]
specialties:               # 전문 시술 2~4개
  - name: "[시술명 예: 발레아주]"
    desc: "[한 줄 설명]"
  - name: "[시술명]"
    desc: "[설명]"
    signature: true        # 대표 시술이면
about:                     # 소개 불릿 2~4개
  - "[경력·강점 예: 前 청담 컬러 전문 5년]"
faq:                       # 자주 묻는 질문 3개 이상 (본문 + AI 인용용)
  - q: "[질문]"
    a: "[답변]"
location:
  address: "[매장 주소]"
  directions: "[오시는 길 예: 강남역 11번 출구 도보 5분]"
knows_about: ["[시술1]", "[시술2]"]   # AI/검색이 읽는 전문 분야
address_locality: "[구·동 예: 강남구]"
address_region: "[시/도 예: 서울]"
```

> 참고용 완성 예시: 저장소의 `designers/hayewoni.yaml`(미입력 상태), `designers/minji.yaml`(전부 채움).

## 1-B. 손님이 AI에 물을 질문 10개 (진단용)

손님이 ChatGPT·Gemini에 실제로 칠 법한 문장으로. (자동 생성 안 함 — 사람이 정함)

```yaml
questions:
  - "[지역] [시술] 잘하는 미용실 추천해줘"      # 예: 강남역 발레아주 잘하는 미용실
  - "[지역] [시술] 잘하는 디자이너 알려줘"
  - "[지역] 근처 [고민] 어디가 좋아"
  # ... 10개 내외
```

# 티어 2 — 카피 품질·노하우 (서비스의 진짜 무기)

## 2-A. 검증된 영업 노하우 (3~5개) ★가장 가치 큼

"실제로 손님을 끌고 매출을 낸" 멘트·가격·컨설팅 방식. 1건당:

```yaml
- title: "[짧은 이름 예: 재방문 시점 각인]"
  category: "[응대전환 | 가격메뉴 | 컨설팅 | SEO 중]"
  principle: "[한 줄 규칙 — 카피에 녹일 핵심 예: 유지기간을 계절과 묶어 다음 방문을 각인]"
  mechanism: "[왜 통하나 — 한 줄]"
  applies_to:
    services: ["[적용 시술]", "또는 * (전체)"]
    signals: ["[이 상황 단어가 있으면 적용 예: 유지, 5~6개월]"]
  example: "[실제로 통했던 멘트 그대로]"
  verified: "[실제 성과 예: 재방문율 45→65% / 객단가 +2만원]"
```

> 채워주실 항목 우선순위: **example(진짜 멘트)**, **verified(실측 성과)** 가 핵심입니다.
> 스키마 참고: `kb/knowledge.yaml`(시드 15개 — 이걸 실데이터로 보강).

## 2-B. 5점 "정답 카피" (1~2개)

원장님이 보기에 "이게 진짜 잘 파는 글"인 프로필/포트폴리오 카피. 루프의 품질 기준선이 됩니다.

```yaml
# 어떤 상황(시술/고객)에 대한 카피인지 + 그 정답 글
case: "[예: 강남 발레아주, 뿌리 자람·손상 걱정 고객]"
reference_copy: |
  [원장님이 직접 쓴 5~7문장 카피 — 이게 만점 기준]
```

> 스키마 참고: `eval/golden_set.yaml` 의 `reference_output`.

# 티어 3 — 모듈·확장 (선택, 있으면 더 풍성)

| 주실 것 | 형식 | 쓰임 |
|---|---|---|
| **메뉴/가격** | 시술명·설명·가격·시간(·시그니처) | 프로필 메뉴판 섹션 |
| **후기** | 별점(1~5)·내용·작성자·시술 | 프로필 후기 위젯(평균 자동 계산) |
| **전후 사진** | before/after 이미지 URL 쌍 + 캡션 | 프로필 드래그 비교 갤러리 |
| **스타일 퀴즈** | 질문·보기(+스타일 태그)·결과 | "어울리는 스타일 찾기" 진단 |
| **발행 URL** | `site_url: https://...` | sitemap·og:url(SEO) |

```yaml
# 티어 3 예시 (디자이너 yaml 에 이어붙임)
site_url: "https://[발행주소]"
menu:
  - name: "[시술]"
    desc: "[설명]"
    price: "[가격 예: 18만원~]"
    time: "[소요 예: 약 2시간]"
    signature: true
reviews:
  - stars: 5
    text: "[후기 내용]"
    by: "[작성자 예: 이○○]"
    service: "[시술]"
portfolio:
  - before: "[before 사진 URL]"
    after: "[after 사진 URL]"
    caption: "[예: 단발 + 발레아주]"
```

# 티어 4 — 운영(선택)

- **API 키**: `GOOGLE_API_KEY`(최소 1개, Gemini 무료 티어면 충분). 무인 자동 진단·콘텐츠 생성 시에만 필요. *개발/루프 자체는 키 없이 Claude로 진행 가능.*
- 네이버/구글 플레이스 운영 권한(있으면): 리뷰·사진·키워드 실제 반영용.
