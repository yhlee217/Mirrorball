# 서비스 개요 브리프 (AI 입력용)

> 이 문서를 AI에게 그대로 주고 "발전 방향을 제안해줘"라고 쓰면 됩니다.
> 1인 컨시어지가 1인 미용실 원장·샵인샵 디자이너에게 제공하는 done-for-you B2B 서비스.

## 1. 한 줄 정의
미용 디자이너가 **녹음·사진만** 하면, 컨시어지의 자동화 도구가 **손님용 프로필(웹/AI 노출)** 과
**디자이너용 고객 관리 앱(카르테·예약·통계)** 을 알아서 만들어 주는 서비스.

## 2. 타깃 / 운영 모델
- **타깃**: 1인 미용실 원장, 샵인샵 헤어 디자이너(예: '부원장'). 마케팅·관리할 시간이 없는 사람.
- **운영자**: 1인 컨시어지(나). 기술·자동화는 컨시어지가 다 함. 디자이너는 녹음·사진만.
- **수익 모델(가설)**: 디자이너에게 월 구독(done-for-you SEO/획득 + 고객관리).

## 3. 설계 원칙 (절대 규칙)
1. **고객 관계는 자동화하지 않는다** — 시스템은 *누구를·왜·뭐라고*만 띄우고, 손님에게 보내는 건 디자이너가 직접.
2. **로컬/무료 우선** — 서버 0원. 정적 사이트 + 폰 로컬 저장(PWA). 유료는 도메인비 정도.
3. **AI 비용은 '쓰는 Claude'로** — 별도 API 결제·키 없이 Claude Code(CLI)로 처리.
4. **사실 기반(환각 금지)** — AI 카피·요약은 주어진 사실만. 과장·의료 단정 금지.
5. **개인정보(PII) 기기/로컬 전용** — 연락처 등은 배포물·공개 repo에 절대 미포함(gitignore).

## 4. 구성 요소 (모두 구현됨, 203 테스트 통과)

### A. 손님용 — 발견·전환
- **프로필 정적 사이트 생성기**(`build.py`/`core.py`/Jinja2): 디자이너 yaml → 한국어+영어 페이지,
  SEO(JSON-LD·sitemap·og), 전후 갤러리·메뉴·후기·스타일 퀴즈 모듈. GitHub Pages 자동 배포.
- **AI 노출 진단**(`diagnose.py`): 손님이 ChatGPT·Gemini·Perplexity에 물을 질문 10개로
  디자이너가 얼마나 언급되는지 측정 → 리포트 + 앱 노출 탭.
- **AI 프로필 카피 자동 생성**(`gen_profile.py`+RAG+`kb/`): 얇은 사실 몇 개 → 발행용 카피
  (tagline·시술설명·소개·FAQ), 검증된 영업 노하우(KB) 주입 + AEO 최적화.
- **QR 코드 생성**(`qr.py`): 예약·프로필 링크 → 인쇄용 카드(거울·명함·인스타).
- **콘텐츠·경쟁 분석**(`content.py`/`compare.py`/`compete.py`), **카드 생성기**(`cards.py`).

### B. 디자이너용 — 고객 관리 앱 (PWA, 직접 추가형)
- **단일 PWA**(`app/`): 홈·오늘 챙길 고객·고객 카르테·통계·AI노출 4탭. iPhone 홈화면 설치.
- **localStorage 로컬 CRM**: 디자이너가 앱에서 직접 고객 추가·수정. 서버 없음, PII 기기 내 저장.
  내보내기/가져오기(백업). 파생(알림·문구·애프터케어·관계)을 앱 안에서 JS로 계산.
- **오늘 챙길 고객 알림**(`build_app.py`): 생일·재방문 주기 → 결정적 산출. **자동 발송 X**.
- **추천 문구 자동 생성**(`drafts.py`): 생일/재방문에 디자이너 말투의 한마디 초안.
- **애프터케어 팁**(`aftercare.py`): 시술별 관리 안내 → 카르테에서 바로 보내기.
- **고객 관계**(`relations.py`): 가족·친구·소개(referral) 연결, 소개한 고객 역산.
- **음성 메모**: 앱 내 실시간 받아쓰기(무료, 브라우저 STT) + 배치 파이프라인(`voicenote.py`:
  녹음→로컬 Whisper 변환→Claude 요약→고객 매칭→카르테 자동 기입). **녹음시각↔네이버 예약시간 자동 매칭**.

### C. 데이터 연동
- **네이버 예약 가져오기**(`import_naver.py`): 파트너센터 CSV → 예약·누적 장부.
- **예약 통계**(`stats.py`): 재방문율·인기 시술·월별 추이·객단가·매출.
- **기존 CRM(핸드SOS 등) 고객 가져오기**(`import_customers.py`): 엑셀/CSV 컬럼 자동 인식 →
  카르테 부트스트랩. 폴더 감시 자동 임포트(`--watch`).

### D. 카피 품질 엔진 (자가개선 루프)
- `copygen.py`+`rag.py`+`kb/knowledge.yaml`(영업 원칙 15개)+`eval/`(루브릭·골든셋)+
  `eval_loop.py`/`run_loop.py`: 생성→LLM 심사→개선→수용/롤백. AEO/GEO 규칙 내장.

## 5. 기술 스택 / 아키텍처
- Python 3.11(파이프라인) + Jinja2(정적 생성) + 바닐라 JS PWA(앱).
- 멀티 LLM(OpenAI·Gemini·Perplexity, 진단용) / Claude CLI(요약·카피, 키 불필요).
- 로컬 Whisper(STT, 무료). 정적 호스팅(GitHub Pages/Cloudflare). localStorage(앱 데이터).
- **백엔드 없음** — 컨시어지 로컬(Mac)에서 도구 실행 → 정적 산출물 배포 + 폰 로컬 저장.
- 데이터: `designers/{slug}.yaml`(공개), `clients/{slug}/`(비공개 PII, gitignore).

## 6. 현재 상태
- ✅ 구현·테스트 완료: 위 A~D 전부. 하예원(부원장·살롱톤·영등포) 프로필 한/영 라이브 발행.
- 🟡 실데이터로 운영 시작 대기: 실제 고객 데이터(일부 입력됨, 로컬), 네이버 예약 CSV, Mac 세팅.
- ⬜ 미결정: 커스텀 도메인, 앱 접근 게이트(Cloudflare Access, 실 PII 올릴 때), 가격·온보딩.

## 7. 차별점 (기존 미용 CRM·핸드SOS 대비)
- 기존 CRM(핸드SOS)이 하는 것: 고객 DB·매출·예약연동·분석 → **겹치지 않게 함**.
- 우리만 하는 것: **AI 검색 노출 진단·최적화**, **AI 프로필 카피 자동 생성·발행**,
  **음성 메모 자동 카르테화**, **손님용 웹 프로필/QR**. (획득·노출 + 가벼운 관계관리)

## 8. 풀어야 할 질문 / 결정
- 핸드SOS 등 기존 데이터 이관(내보내기 여부 미확인) vs 지금부터 쌓기.
- 여러 기기 동기화(현재 기기 1대 로컬) — 필요해지면 경량 백엔드.
- 가격·패키징, 동시에 몇 명까지 1인 컨시어지가 운영 가능한지(스케일 한계).
- 실시간 예약 동기화 불가(네이버 API 제휴 필요) → 스냅샷 모델 유지.

## 9. 발전 방향 브레인스토밍용 힌트 (AI가 여기서 확장)
- 획득(노출·프로필) ↔ 유지(카르테·재방문) 중 어디에 더 투자할지?
- "녹음만 하면 다 됨"을 더 매끄럽게(친링크·자동 매칭 정확도)?
- 컨시어지 1인의 운영 레버리지(다수 디자이너 동시 운영 자동화)?
- 손님 경험(프로필→예약 전환, 리뷰·재방문 유도)?
- 수익화·패키징(티어, 성과 기반 과금)?
