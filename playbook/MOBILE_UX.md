# 모바일 편의성 다듬기 (2026-10-13)

> 요청: "현재 UI도 불편한 거 같아. 모바일에서 봤을 때 편의성을 좀 더 고려해줘."
> 방법: 7개 화면을 견본으로 그려 폰 폭 390px·360px(보급형 안드로이드)·320px 에서 재고(`web/scripts/ui-audit`), 코드로 이동·입력 흐름을 따라가 봤다.

## 찾은 것

| # | 무엇 | 근거 |
|---|---|---|
| 1 | **360px 에서 챙길 고객 이름이 한 글자씩 세로로 쪼개짐** | 뱃지 + '선불 52만' + 문자·전화 버튼에 밀려 이름 칸이 한 글자 폭이 됐다(김/서/연) |
| 2 | 360px 에서 통계 '약 2,250만'·'약 7,604만'이 잘림, 320px 에서 카르테 띠가 잘림 | 세 칸·네 칸이 폭에 비해 숫자가 크다 |
| 3 | 고객 목록 조건 칩 다섯이 360px 에서 두 줄 | '필터'가 다음 줄로 밀려 목록이 한 줄 내려간다 |
| 4 | **'‹ 홈'이 늘 홈으로** | 고객 목록 → 카르테 → '‹ 홈' 이면 목록이 아니라 홈. 홈 화면에 설치한 앱엔 브라우저 뒤로 버튼이 없다 |
| 5 | **돌아오면 검색·조건이 사라짐** | 고객 목록 검색어·조건, 챙길 고객 '더 보기'·펼친 줄이 화면 상태라 다른 화면에 다녀오면 처음부터 |
| 6 | 카르테에서 전화·문자를 못 함 | 번호가 화면에 없어 챙길 고객 탭이나 연락처 앱으로 가야 했다 |
| 7 | 긴 목록을 내리면 검색 칸이 사라짐 · 설정 저장 버튼이 긴 양식 맨 끝 | 다시 위로·아래로 끝까지 밀어야 한다 |
| 8 | 누르는 곳이 작음 | 💬·📞 37px · 알약 35px · 조건 칩 31px(손가락 권장 44px) |
| 9 | 숫자 입력에 기호 키보드 | 설정의 숫자 칸이 type=number — 아이폰에서 숫자 패드가 아니다 |
| 10 | 아이폰 홈 표시줄 | 홈 화면 앱에서 아래 탭바가 홈 표시줄 영역을 고려하지 않았다 |

## 고친 것

- **좁은 화면**: 이름은 한 줄로 고정하고 뱃지만 다음 줄로 · 380px 이하에선 문자 버튼을 💬 아이콘만(이름 자리) · 통계 숫자 17px · 조건 칩 여백을 줄여 한 줄 · 350px 이하 카르테 띠 2×2.
- **뒤로**: '‹ 뒤로' — 앱 안에서 넘어왔으면 그 화면으로, 링크로 처음 연 화면이면 홈(앱 밖으로 나가지 않게, `components/back-button.tsx`). 고객 탭의 '‹ 홈'은 뺐다(탭 화면 — 챙길 고객·방문과 같게).
- **상태 유지**: 고객 목록(검색·조건·정렬·필터 펼침)과 챙길 고객(펼친 수·열린 줄)을 주소에 담는다(`lib/list-state.ts`). 돌아오면 같은 상태 · 같은 길이라 스크롤 자리도 돌아온다.
- **바로 연락**: 카르테 머리말에 📞·💬(44px). 챙길 고객 대상(뱃지가 있는 분)일 때만 '연락함'으로 남긴다 — 예약 확인 전화까지 세면 연락 효과가 부푼다. 홈 예약을 펼치면 📞 전화.
- **손가락**: 고객 목록 검색 줄은 위에 붙고 · 설정 '저장'은 화면 아래(탭바 위)에 붙는다 · 💬·📞 44px, 알약 40px, 조건 칩 36px.
- **키보드**: 숫자 칸은 숫자 패드 · 검색은 키보드 '검색'을 누르면 키보드가 닫혀 결과가 보인다.
- **아이폰**: 탭바·본문·알림이 홈 표시줄만큼 비켜 선다(viewport-fit=cover + safe-area).

## 확인

UI 측정에 **'360px 에서 가로 넘침 · 잘린 글자 · 쪼개진 이름 0'**을 더했다(고치기 전 4곳 → 0). 누르는 곳 44px 미만 94 → 77곳, 24px 미만 0곳 유지. 첫 화면 목표(고객 목록 10줄 등)·글자·대비 목표 모두 그대로 통과. 테스트: `tests/test_list_state.py`(주소 ↔ 상태).
