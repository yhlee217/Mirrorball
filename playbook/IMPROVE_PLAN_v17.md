## 1. 할 것

### P0 쉬는 동안 앱이 틀린 말을 하지 않게
- 자료가 8일 넘게 멈추면(앱의 '수집 밀림'과 같은 기준) 홈 맨 위에 한 줄: '자료는 10.21까지예요 — 그 뒤 예약 · 방문은 아직
  안 보여요'. 날짜는 마지막 수집에서 읽는다 — 따로 켜고 끄는 값이 없어, 수집이 다시 돌면 저절로 사라진다.
- 챙길 고객 — 같은 상태면 목록 위에 '10.21 뒤에 오셨을 수 있어요 — 연락 전에 HandSOS 에서 마지막 방문을 확인하세요'.
  펼친 줄의 보내기 버튼 옆에도 짧게.
- 홈 '오늘 예약' — 받아 둔 예약이 없는 날이면 '예약은 10.21에 받은 것까지 — 오늘 예약은 HandSOS 에서'.
- 통계 · 카르테는 그대로 둔다(지난 기록이라 틀린 말은 아니다) — 날짜 칩만.

### P1 DB 가 혼자서도 깨어 있게
- 한 달에 두 번 도는 작은 예약 작업이 매일 감시와 자기 자신을 다시 '켜기'(`gh workflow enable`, 권한 `actions: write`)로
  건다 — 빈 커밋 없이 60일 규칙을 넘기려는 것이다. 이 방법은 공식 문서가 아니라 널리 쓰이는 방식이라, 만들 때 실제로
  60일이 다시 세어지는지 확인하고, 안 되면 한 달 한 번 작은 커밋(배포가 괜히 돌지 않게)으로 바꾼다.
- 1.10 확인 예약(사람 손)은 그대로 둔다 — 위 작업이 잘 도는지도 그때 함께 본다.

### P2 가격표 — 맥에서 한 번(읽기만)
- 운영자: 아래 한 줄 → 결과를 붙여 주시면 하예원 부원장 시술별 가격표로 정리한다. 손님 정보는 읽지도 찍지도 않는다.

```bash
cd ~/Dev/Mirrorball && git pull origin claude/charming-planck-hmgazi && .venv/bin/python worker/price_probe.py
```

### 다음 — 앞으로의 길(§4-3)을 정한 뒤
- 쉬면서 기다리기 → 더 할 것 없음(P0 · P1 로 충분)
- 디자이너가 직접 남기기 → 방문 · 예약을 앱에서 한 번 눌러 남기는 화면(챙길 고객이 다시 맞아진다)
- 수집 다시 켜기 → 맥 로그(조용한 실패)부터, 밀린 기간 전체를 채우는 밀린 수집(지금은 14일치만), 그다음 재개
- 앱 접기 → 손님 정보 지우기(개인정보) · 디자이너 메모는 파일로 드리기 · 서비스 정리 순서

## 2. 하지 않을 것
- **HandSOS 파일 · 생일 · 서면 승낙에 기대는 일** — 확인된 사실(§7). 다시 묻지 않는다.
- **수집 재개** — 운영자 결정 전엔. 결정이 나면 위 '다음'의 순서로.
- **새 기능(주간 알림 · 연락 흐름 고치기 · 앱 첫 열기 줄이기 등)** — 데이터가 멈추고 사용이 0인 동안엔 효과를 잴 수 없다.
