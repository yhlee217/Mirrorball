# 인스타그램 발견 지표 — Instagram Graph API 도입 보고서

> 목적: 미용업에서 강력한 인스타그램 홍보·노출을 **합법·안정적으로 모니터링**하고,
> 네이버 발견 점수처럼 **지표(언급량·점유율·트렌드·인게이지먼트)** 로 추세화한다.
> 결론: 유령계정 스크래핑이 아니라 **Instagram Graph API(비즈니스 계정 기반)** 로 가능. 단, 한계가 명확하다.

---

## 0. TL;DR (한 문단)

살롱 인스타를 **비즈니스/크리에이터 계정**으로 두면, Meta 공식 **Graph API**로 ①우리 멘션·태그
②경쟁 *비즈니스 계정*의 게시물·인게이지먼트 ③해시태그 인기/최근 게시물을 **밴 위험 없이** 가져올 수 있다.
이를 묶어 **인스타 발견 점수**(언급·점유율·트렌드·인게이지먼트)를 주간 추세로 만들 수 있다.
**단 두 가지 한계가 설계를 좌우한다: (1) 개인계정은 안 보인다, (2) 해시태그 '총 게시물 수'는 API가 안 준다(샘플링으로 근사).**

---

## 1. Instagram Graph API란

- Meta(페이스북)의 Graph API 일부로, **인스타 비즈니스/크리에이터 계정**이 자기 데이터와 *일부 공개 데이터*를
  프로그램으로 조회하게 해주는 공식 통로. (개인 계정용 Basic Display API와 다름 — 그쪽은 모니터링에 부적합.)
- **유령계정·스크래핑이 아님** → ToS 위반·밴·차단 리스크 없음. 주간 자동 실행에 안정적.

### 전제조건(1회 셋업)
1. 살롱 인스타 → **비즈니스 또는 크리에이터 계정**으로 전환(무료, 5분)
2. **Meta 개발자 앱** 생성(무료) + (계정에 따라) 페이스북 페이지 연결
3. **액세스 토큰** 발급: 단기(1시간) → **장기(60일)** 또는 **시스템 유저 토큰(무기한)** — 주간 잡엔 장기/시스템 토큰
4. 권한(앱 검수 필요할 수 있음): `instagram_basic`, `instagram_manage_insights`,
   `instagram_manage_comments`, `pages_show_list`, `business_management`
   - **본인(살롱) 계정 데이터**만 쓰면 개발 모드에서 검수 없이 가능. 타 계정 공개데이터 조회는 검수 권장.

## 2. 모니터링에 쓸 수 있는 엔드포인트

| # | 기능 | 엔드포인트(개념) | 주는 것 | 한계 |
|---|---|---|---|---|
| A | **해시태그 검색** | `ig_hashtag_search` → `{hashtag-id}/recent_media`·`/top_media` | 해당 해시태그의 **최근/인기 게시물**(caption, like_count, comments_count, permalink, timestamp) | **총 게시물 수(media_count) 미제공.** 7일당 **해시태그 30개**까지. recent_media는 최근 일부만 |
| B | **비즈니스 디스커버리** | `business_discovery.username({user})` | 상대 **비즈니스 계정**의 followers_count, media_count, 최근 게시물 + 좋아요/댓글 | **개인·비공개 계정 안 보임** |
| C | **멘션·태그** | `{ig-user}/tags`, mentions edge/webhook | 우리 계정이 **@멘션·태그된 미디어/댓글** | 우리 계정 대상(비즈니스) |
| D | **내 계정 인사이트** | `{ig-user}/insights` | 도달·노출·프로필 방문·팔로워 증감, 게시물별 인게이지먼트 | 내 계정만 |

> 핵심: A는 "시장/트렌드", B는 "경쟁사", C는 "우리 언급", D는 "우리 성과"를 담당.

---

## 3. 우리가 원한 4개 지표 매핑 (어디까지 정확한가)

### ① 언급량 (디자이너 개인 포함)  — ⚠️ 근사
- 방법: `#하예원` `#살롱톤` `#살롱톤하예원` 등의 **recent_media/top_media를 매주 샘플링**해 개수·인게이지먼트 집계.
- 한계: 총량(media_count)이 없어 **주간 스냅샷 델타**로 "이번 주 새 언급 ≈ N"을 근사. 완전 정확치는 아님.

### ② 점유율 (SoV — 경쟁 대비 "어느 정도 있지")  — ⚠️ 근사·부분
- 방법: 우리 언급량 ÷ (우리 + 경쟁사들 언급량). 디자이너 단위로도 `#하예원` vs 경쟁 디자이너 해시태그.
- 한계: 경쟁사가 **개인계정이면 계정 지표(B)는 빠지고 해시태그 언급(A)만** 잡힘 → 점유율은 "해시태그 기준"으로 정의해야 일관됨.

### ③ 해시태그 트렌드 (손님이 뭐에 반응하나)  — ✅ (근사지만 유효)
- 방법: `#영등포레이어드컷` `#영등포뿌리펌` `#레이어드펌` 등 지역×스타일 해시태그의 **주간 인기 게시물 인게이지먼트·게시 빈도** 추세.
- 가치: 가장 빨리 크는 스타일 = 지금 반응하는 것 → **네이버 처방과 결합**("레이어드펌이 인스타도 뜨고 네이버 4위 → 올인").

### ④ 경쟁 인게이지먼트  — ✅ (비즈니스 계정 한정)
- 방법: 경쟁 **비즈니스 계정**의 팔로워·최근 게시물 평균 좋아요/댓글(B) → 우리(D)와 비교.
- 한계: 개인계정 경쟁사는 제외.

→ 4개를 가중 결합해 **인스타 발견 점수(0~100)** + 주간 추세. (네이버 발견 점수와 동일 구조)

---

## 4. 한계·리스크 (정직하게)

1. **개인계정은 안 보인다** — 소규모 디자이너가 개인계정이면 B/D에서 빠짐. (해시태그 언급 A로는 일부 포착)
2. **해시태그 총 게시물 수 미제공** — "언급량"은 샘플링 델타로 근사. 절대수치 아님.
3. **레이트 리밋** — 해시태그 7일당 30개. 키워드 엄선 필요(지역×핵심스타일 + 우리/경쟁 브랜드 태그).
4. **검색 노출 순위 불가** — 인스타 검색/탐색 랭킹은 API가 안 줌. top_media가 가장 가까운 대체.
5. **앱 검수** — 타 계정 공개데이터·고급 권한은 Meta 앱 검수가 필요할 수 있음(본인 계정만이면 불필요).
6. **API 정책 변동** — Meta는 엔드포인트·정책을 주기적으로 바꿈. 깨질 수 있으나 **스크래퍼보다 훨씬 안정적**.

## 5. 권고 설계 (Mirrorball 통합)

발견 케어(`expose.py`)와 **같은 패턴**으로 분리:

```
insta_collect.py   # Graph API 수집기 (토큰은 secrets/instagram.yaml, git 제외)
   ├─ A 해시태그 샘플링(지역×스타일 + 우리/경쟁 태그)
   ├─ B 경쟁 비즈니스 계정 디스커버리
   ├─ C 우리 멘션·태그
   └─ D 내 계정 인사이트
        ▼
insta.py           # 결정적 지표 엔진(언급·점유율·트렌드·인게이지먼트 → 점수)
   → clients/{slug}/instagram.yaml → 앱 '발견' 탭의 '인스타' 섹션 + 주간 추세
```

- **secrets/instagram.yaml**(git 제외): `access_token`, `ig_user_id`, 추적 해시태그·경쟁 username 목록.
- **주간 스케줄러**: 기존 `run_expose_auto.bat`에 인스타 수집을 한 단계 추가(또는 별도 작업).
- **추세·변화 추적**: 네이버처럼 `history`에 스냅샷 → "이번 주 점유율 6%→9%", "레이어드펌 언급 ▲".

## 6. 도입 체크리스트 & 공수

| 단계 | 내용 | 공수 |
|---|---|---|
| 1 | 살롱 인스타 → 비즈니스 계정 전환 | 5분(사장님) |
| 2 | Meta 개발자 앱 + (필요시)페이지 연결 | 20~40분 |
| 3 | 장기/시스템 토큰 발급 + secrets/instagram.yaml | 20분 |
| 4 | 추적 해시태그·경쟁 username 확정(30개 한도 내) | 30분 |
| 5 | insta_collect.py / insta.py 구현 | 개발 |
| 6 | 앱 '인스타' 섹션 + 주간 스케줄 연결 | 개발 |

- **비용: 0원**(Graph API 무료). 토큰 갱신만 관리(시스템 토큰이면 무기한).

## 7. 결론

- **가능하다.** 유령계정 없이 공식 API로 ①~④를 주간 지표화할 수 있고, 발견 케어와 한 화면에 붙는다.
- **단, "개인계정 비가시성"과 "해시태그 총량 미제공"** 때문에 일부 지표는 **근사**다 — 이를 숨기지 않고
  "해시태그 기준 점유율", "샘플링 델타" 로 **정직하게 정의**해야 신뢰가 산다(네이버에서 한 것과 동일 원칙).
- 추천: **점유율(SoV)을 1순위 지표**로, ③트렌드를 네이버 처방과 결합하는 형태가 ROI가 가장 크다.
